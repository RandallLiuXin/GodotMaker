# GodotMaker v1.0.0

GodotMaker 1.0 establishes the first stable contract for turning a game design
into a tested Godot project through coding-agent Skills. This release centers
the pipeline on first-class 2D Asset Skills, deterministic Godot-native
resources, and evidence-backed handoff between Asset, Build, Verify, Evaluate,
and FixGap stages.

> Existing `0.x` workspaces cannot be upgraded incrementally. Back up the
> project, then run `python tools/publish.py --force <target>` to cleanly
> re-initialize the framework for `v1.0.0`. This skips old migrations and
> re-baselines the migration tracker after re-deploy. It does not convert
> project documents such as `GDD.md`, `PLAN.md`, or `ASSETS.md`; review or
> regenerate incompatible documents before continuing the pipeline.

## Added

- Added first-class Asset Skills with typed request/result contracts for the
  supported 2D production families, including characters, animated effects,
  UI and card kits, tilesets, props, backgrounds, platform strips, and screen
  references.
- Added deterministic Godot-native compilers for `Texture2D`, `AtlasTexture`,
  `StyleBoxTexture`, `Theme`, `SpriteFrames`, and `TileSet` resources.
- Added fail-closed L0-L4 validation that binds provider source claims,
  normalized images, compiler receipts, final artifacts, and real headless
  Godot `ResourceLoader` checks before an asset can reach a worker.
- Added deterministic atlas assembly, fixed-grid and connected-component sheet
  recovery, marching-squares-15 and blob-47 tileset profiles, and reusable
  nine-slice UI surfaces (#169).
- Added Pi as a supported coding-agent runtime alongside Claude Code, Codex,
  and OpenCode.
- Added evaluator evidence handoff for FixGap and an optional Phantom Camera
  supporting Skill.

## Changed

- `ASSETS.md` is now the single runtime asset catalog. Each generated or
  provided asset records its final Godot resource type and loadable `res://`
  path directly, and multi-output families register every declared resource
  atomically.
- Asset generation now writes deterministic
  `assets/generated/<asset_type>/<asset_id>/` outputs and publishes the
  shared compiler, schema, and validation runtime under
  `.godotmaker/asset-runtime/` for every supported agent.
- Build and FixGap workers receive minimal runtime snapshots from `ASSETS.md`
  and bind validated Godot resources instead of reconstructing them from
  provider source images (#97).
- Reference-only families stop at `source_ready`; only native artifacts that
  pass their complete registration chain become `generated` worker inputs.

## Fixed

- Screen references now claim successful Codex-generated images before final
  validation and use deterministic proportional cover cropping so transparent
  canvas edges cannot invalidate an otherwise usable reference (#180) —
  @RandallLiuXin.
- Failed compilation and registration paths retain the previous stable
  artifact, reject stale same-path regenerations, and commit multi-output asset
  rows only after every declared runtime resource validates.
- Restored real headless Godot validation for Theme and TileSet resources,
  including imported atlases, safe resource paths, texture decoding, font
  loading, terrain masks, and seam diagnostics.
- Asset-stage resume, retry, and completion bookkeeping now preserves one
  consistent terminal status and keeps actionable blockers on partial results.

## Removed

- Removed the legacy generated-asset runtime manifest, stable-entry layer, and
  duplicated production-unit documents. `ASSETS.md` and each first-class Asset
  Skill are now the authoritative runtime and execution contracts.

## Known limitations

- MAJOR clean re-initialization does not migrate project documents from `0.x`;
  incompatible GDD, plan, and asset contracts must be reviewed or regenerated.
- Real-provider image quality and private evaluator evidence are not implied by
  the source-tree L0-L4 validation suite; provider availability, credentials,
  and model behavior remain external dependencies.
- OpenCode image generation remains subject to the capabilities exposed by the
  selected OpenCode provider and runtime.
